# 2026.10.29 软件更新：IMU 与舵机分别显示状态

本版通过软件包更新现有卡，无需重新烧录镜像。发布页：
[2026.10.29 软件更新](https://github.com/fanhao375/microduck-replica/releases/tag/microduck-software-v2026.10.29)。

## 修复了什么

主程序等待 IMU 时，会继续报告已经收到的舵机回包。网页可以同时显示
“舵机 15/15 在线”和“等待 IMU 数据”，也能按 ID 区分“有应答、未应答、未知”。
位置原始值、电压和温度以实际回包为准；旧数据过期后回到未知。

运动模式和出厂标定模式的启动检查均支持独立设备诊断。
IMU、标定、卸力确认和运动准入条件继续生效；诊断读数用于显示设备状态。
IMU 缺失时不再统一猜测“舵机没上电”。

## 已有网页“软件更新”入口

1. 打开鸭子原来的控制网址，登录，进入 **设置 → 软件更新**。
2. 点 **检查更新 → 下载更新**；无法联网时，在电脑下载发布页的
   `2026.10.29.software-update.tar`，在同一页上传完整离线包。
3. 按页面完成准备检查：停止策略、关闭语音和音乐，结束录制、回放、舵机和
   标定会话，保持供电。旧升级器的第一阶段仍使用原有准备条件。
4. 点 **立即更新**，等待网页重新连接，核对网页版本为 `2026.10.29`。
5. 要启用完整的独立诊断，再在同一页找到 **主程序更新**。承托鸭子并确认卸力，
   按页面明确确认后安装主程序，等待实际运行身份核验。
6. 刷新总览与舵机页。新版主程序标识末尾为 **`.46`**，接口 API 为 **41**。

网页层和主程序分两次更新。网页显示新版号，只代表网页层已更新；主程序也
更新完成后，才会提供新增的独立设备回包。已安装 `.46` 的设备无需重复安装主程序。

可自动升级的原生主程序包括本项目已核验的 `.44`、`.45` 构建。未知自定义
二进制和启动方式继续要求维护者核对，页面保留具体拒绝原因。若旧版在 IMU
缺失或首次标定状态下无法完成准备检查，请保留现场日志，由维护者处理；
不要为了通过升级检查而强行站立。

原有 Wi-Fi、配对、动作、模型、API Key、参数与标定继续保留。
IMU 来源与安装方向仍按实际硬件配置；更换主板、IMU 或安装方式后，应重新核对
本机标定，尤其不要把原鸭子的方向和零位直接当作另一只鸭子的标定结果。

## 旧卡没有更新入口

使用同一发布页的 `microduck-bootstrap-20261029.tar.gz` 和对应校验文件，按
`bootstrap-README.txt` 安装一次兼容的升级入口，之后使用上述网页流程。
引导包沿用原发行公钥，资源、签名和兼容性检查照常执行。

## 实际验证范围

本次已在一块 Radxa ZERO 3 上保持所选 I²C IMU 无数据的状态，确认网页仍显示
十五个舵机在线，并取得各舵机原始位置、电压和温度；主程序保持等待，舵机卸力。
站立、行走及不同 IMU 实物的运动效果不属于这次显示修复的验收范围。
