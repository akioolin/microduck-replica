# 只接 IMU 也能在网页查看诊断

软件 2026.10.30 增加独立的总线 IMU 只读诊断。只连接 ID 200 的 IMU、没有
连接舵机，或只接部分舵机时，主程序在等待完整设备的过程中仍会尝试读取 IMU。
网页总览和 IMU 页面分别展示 IMU 和舵机状态。

这是诊断信息：识别到板卡、读到一个样本、确认安装方向和整机允许运动，是不同
的条件。识别结果不会放行站立、行走、舵机使能或标定写入，也不作为校准后的
整机姿态使用。缺少设备时，主程序继续等待并显示原来的启动原因。

## 已有设备如何更新

发布页：[软件 2026.10.30](https://github.com/fanhao375/microduck-replica/releases/tag/microduck-software-v2026.10.30)。

1. 原控制网页 → **设置 → 软件更新**，检查、下载并按准备检查安装 `2026.10.30`。
   不能联网时，从发布页下载完整的 `2026.10.30.software-update.tar`，上传离线包。
2. 网页重新连接、确认版本后，在同页 **主程序更新** 中，按提示承托、卸力，
   明确确认后安装主程序 **`.47` / API 42**。只更新网页还没有新的设备观测数据。
3. 更换接线前断开硬件电源。按所选主板和接口的说明接入 IMU，确认供电后再开机。
4. 打开 **总览** 或 **IMU** 页，查看“总线 IMU 只读诊断”。不必为此启动策略。

升级保留原来的网络、配对、模型、动作、API Key 和个人标定，无需重新烧卡。
主程序更新支持本项目已核验的 `.44`、`.45`、`.46` 构建，未知二进制和未完成
的旧升级事务继续按具体原因拒绝，不能自行删除保护记录。

原版本的准备检查仍然有效。如果当前只接 IMU、旧版因设备不全无法进入升级
准备状态，先在完整设备上按流程完成升级，或由维护者按受控流程处理；不要
为了通过检查强行站立、伪造状态或绕过保护。没有升级入口的兼容旧卡，使用
发布页的 `microduck-bootstrap-20261030.tar.gz`，由维护者按附件说明安装入口。

## 如何理解显示结果

| 网页诊断 | 含义 |
| --- | --- |
| 已识别／读到诊断样本 | 已取得当前板卡响应和相应信息，仍不代表整机就绪 |
| 有应答、类型或数据待确认 | 板卡回应了，但身份、样本、状态或连续性未完成确认 |
| 无应答 | 本次诊断未收到有效回应，检查供电、接线、波特率和所选配置 |
| 数据过期／未知 | 证据已过期、连接中断，或主程序没有提供独立诊断字段 |

主程序采集时间与网页服务接收时间共同决定证据是否有效。停止采集后，重复读取
缓存不会让旧数据重新变成“刚读到”。未识别的身份不会冒充本项目 IMU。

诊断遵循当前实际配置。使用总线板卡时应选择总线来源；若仍选着 I²C 模块，
系统不会因为总线上接了 ID 200 而偷偷切换来源。默认旧协议支持已知的 Feetech
板卡及兼容 DXL2 布局；Qinmo 使用其独立配置，不自动按另一套陀螺量程解释。
更换来源、协议、板卡或安装方式后，按实际硬件重新核对方向和标定。
